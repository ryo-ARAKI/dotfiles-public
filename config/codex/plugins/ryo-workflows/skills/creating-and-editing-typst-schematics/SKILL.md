# Create and Edit Typst Schematics

Turn scientific relationships into editable Typst figures, using CeTZ or a simpler appropriate method.
Preserve the supplied meaning and the receiving document's settings.
Qualitative spectra and profiles belong here even when they have axes and curves; measured or computed data plots belong to the numerical figure skill.

## Scope and mode

- **New figure:** establish the meaning and receiving conditions, compare 2–3 distinct compositions as static previews plus a self-contained editable HTML, then wait for the user's exported composition before making the final Typst figure.
- **Revision:** read the latest source, output, and user edits; distinguish the requested delta from any source/output mismatch.
  A local correction need not repeat composition proposals or browser editing.
- **Read-only review:** inspect source, meaning, and rendered output; return evidence and gaps without changing delivered files.
  Compile candidates only into temporary locations.

Identify the question, required elements, relationships and directions, containment, correspondences, legend encodings, qualitative versus measured quantities, supplied assets and their provenance, receiving dimensions, language, and formats.
Use existing specifications or notes for this contract; require no new scientific schema.
Ask only result-changing missing information, one question at a time, and continue independent parts.
Do not invent a direction, causal claim, area interpretation, missing image, or mathematical definition.

## Deliver verified candidates

For new compositions, the user's browser edits are the layout input.
The user exports one versioned JSON file and attaches it or supplies its location; do not rely on chat-only controls or automatic transmission.
Keep the final unrounded snapshot, preserve untouched IDs on redraw, and derive tidy Typst coordinates while preserving alignment, spacing, dimensions, containment, text, colors, and connections.
Show any composition-changing cleanup beside the accepted draft and wait for the affected adjustment.
Fixture exports during skill testing are test evidence, never evidence of a person's agreement.

Verify required elements and relationships against the contract, then compile standalone and affected receiving contexts.
Inspect PDF page count/dimensions, extracted labels, and rendered pages at the actual publication size; compare the final figure with the accepted draft at the same aspect ratio.
Keep figure text, mathematics, and strokes editable rather than delivering only a rasterized diagram.
Use the existing document's typography; figure bodies must not alter document-wide page, text, numbering, bibliography, or slide progression.

Stage outputs separately and preserve previous successful artifacts until the affected set passes.
On missing dependencies, save failures, incompatible snapshots, unreadable labels, or broken inclusion, retain existing edits and report the dependent work as incomplete.
Never silently downgrade packages or update environments without authority.
Report source/input identities, chosen package versions and verification date, compiler/fonts, rendered contexts, checks, and gaps.
This skill grants no installation, deployment, Git, or external-write authority.
