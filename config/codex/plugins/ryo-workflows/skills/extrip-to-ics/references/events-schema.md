# 正規化イベントJSON

Markdownの書式差をエージェントが読み取り、スクリプトへ以下のJSONを渡す。
自動抽出済みと仮定せず、原文と各フィールドを照合する。
中間JSONには予約情報が含まれるため、共有・バージョン管理の対象へ不用意に加えない。

```json
{
  "events": [
    {
      "id": "2026-11-04-sample-outbound",
      "group": "20261104-05",
      "summary": "のぞみ241号 東京→京都",
      "start": "2026-11-04T08:39:00+09:00",
      "end": "2026-11-04T10:50:00+09:00",
      "all_day": false,
      "map_query": "東京駅",
      "description": "東京駅08:39 → 京都駅10:50\n座席など原文の予約情報",
      "source": "20261104-05.md"
    },
    {
      "id": "2026-11-04-sample-hotel",
      "group": "20261104-05",
      "summary": "ホテル名",
      "start": "2026-11-04",
      "end": "2026-11-06",
      "all_day": true,
      "map_query": "ホテル名 住所",
      "description": "宿泊期間：2026/11/04～11/05（1泊）\n予約番号・チェックイン等の原文情報",
      "source": "20261104-05.md"
    }
  ]
}
```

全フィールドが必須。`id` はイベントを識別する安定した任意の文字列で、バッチ内で一意にする。
予約番号・旅行開始日・往路／復路／ホテル等を組み合わせ、時刻や座席の変更で変えない。
同じイベントの再生成でも同じ `id` を使う。ファイル名や時刻の一致だけで既存Google予定との対応を仮定しない。

`group` は旅行別出力のファイル名（拡張子なし）。英数字・ハイフン・アンダースコアのみ。
`source` は元ファイル名。`description` には実際の改行をJSONの `\n` として記述する。
TEXTエスケープやURLエンコードはスクリプトに任せる。

`all_day: false` はISO 8601のUTCオフセット付き日時、`true` は `YYYY-MM-DD` の日付。
いずれも終了は開始より後。終日終了日はその予定に含まれない。
この例は4日チェックイン・5日チェックアウトを4～5日の2日分で表示する。
